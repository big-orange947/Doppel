# Assertion/context separation and explicit isolation, 2026-11-13

This round changes representation and invalid-item handling, not an LLM prompt
benchmark score. Original stopped pilots and ledgers remain untouched. No new
paid API, embedding, Graphiti, real-chat or Docker invocation occurred.

## Implementation

New module-only `SourceAssertionPersonalMemoryAnalyzer` stores each exact,
unambiguous source clause as candidate content and references the original source
with identity, code-point offsets and full-text checksum. Original messages stay
in the existing Store. `assemble_source_assertions` validates supplied authorized
sources against authoritative assertion records, returning multiple clauses with
one deduplicated source message. It does not authorize users or fetch Store data.
Ordinary queries do not auto-assemble context; callers must supply full evidence.

Default invalid policy remains reject_batch. Explicit isolate requires a diagnostic
observer and accounts for each rejected raw index with a closed reason code.
Schema-invalid values and bad source/time references are not coerced or repaired.
Top-level errors and excessive counts still stop. Observer failure stops before
returning any analysis; durable diagnostic persistence belongs to the host.
Unknown interpretations, unsupported predicates, incorrect type/topic labels or
wrongly selected but verbatim clauses may still survive; this is not semantic
verification. Isolating schema errors alone cannot fix a meaningful wrong claim.

V1 source-clause extraction was factored into private generation/conversion helpers;
its prompt, schema, version hash, full-source policy and all-or-nothing validation
stay unchanged. Defaults and root APIs are not replaced. No migration or reset.
